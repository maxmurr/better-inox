Feedback tells you whether your work moved you closer to a goal. You can use it
to correct a mistake or repeat what worked.

Software engineers solve problems through iteration. We make a change, observe
the result, and use that feedback to decide what to do next.

Suppose you work on a web calendar that helps patients schedule appointments.
Doctors set their availability, and patients choose a time slot. Now patients
need to ask their doctors questions in the app, so you must add a **chat
interface**.

You build a page, components, and interactions with the backend API. But **how
do you know it works?**

Run the app and check whether the page loads and users can send messages. If the
code does not compile, fix it and try again. The app may then load, but fail to
send messages. Fix that issue and repeat.
