**Readability** is the first part of a test's maintainability. It measures how
easy the test is to understand.

Compare the two tests again:

**Test case 1**

```ts
test('test1', () => {
  const a = new BankAccount(100);
  let x = 0;
  for (let i = 0; i < 1; i++) {
    x = a.withdraw(40);
  }
  expect(x).toBe(60);
});
```

**Test case 2**

```ts
describe('BankAccount.withdraw', () => {
  it('reduces the balance when withdrawing less than available funds', () => {
    // Arrange
    const account = new BankAccount(100);

    // Act
    const remainingBalance = account.withdraw(40);

    // Assert
    expect(remainingBalance).toBe(60);
  });
});
```

The first test has a vague description, cryptic variable names such as `a` and
`x`, and an unnecessary `for` loop. These choices make it hard to understand.

The second test names the scenario, action, and expected result. It also
separates the three stages of the xUnit pattern: **Arrange** the test data,
**Act** on the subject, and **Assert** the expected result.
