Poorly designed tests are hard to read and maintain. A suite full of brittle
tests can cost more than it saves.

Well-written tests let us refactor with confidence. Let's start with their first
quality: readability.

**Example**

Suppose a banking app lets customers deposit and withdraw money. Compare these
two tests for withdrawals:

**Test case #1**

```ts
test('test1', () => {
  const a = new BankAccount(100);
  let x = 0;
  for (let i = 0; i < 1; i++) {
    x = a.withdraw(40);
  }
  expect(x).toBe(60);
});
```

**Test case #2**

```ts
describe('BankAccount.withdraw', () => {
  it('reduces the balance when withdrawing less than available funds', () => {
    // Arrange
    const account = new BankAccount(100);

    // Act
    const remainingBalance = account.withdraw(40);

    // Assert
    expect(remainingBalance).toBe(60);
  });
});
```
