Unit tests cover smaller pieces of code in our applications - they are generally
tied to specific functions, classes, or a group comprised of both components.
The fact that this type of test is more coupled to the production code makes it
also slightly more brittle than the high-level tests. Hence, we have to be extra
careful to ensure they are valuable and less coupled to implementation details.

To create and validate the quiz fields, we have the _createQuizModel()_ function
presented earlier. Suppose it has the following steps:

```ts
export function createQuizModel(form: QuizForm): QuizModel {
  // Validation below
  const validatedTitle = validateTitle(form);
  const validatedQuestions = validateQuestions(form);
  const maybeError = validateAnswers(
    validatedQuestions.flatMap((q) => q.answers)
  );
  if (maybeError instanceof Error) {
    throw answersOrError;
  }

  return {
    title: validatedTitle,
    questions: validatedQuestions,
  };
}
```

When deciding what should be unitarily tested, we have a few options:

- _validateTitle()_ function
- _validateQuestions()_ function
- _validateAnswers()_ function
- _createQuizModel()_ function
