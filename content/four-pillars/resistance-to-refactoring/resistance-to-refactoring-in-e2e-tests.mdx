End-to-end (E2E) tests are the final level of the test pyramid. They often use
the same tools and structure as integration tests, but need more configuration
because they rely on production-like dependencies.

Here is the E2E test for creating a quiz:

```ts
describe('Create Quiz', () => {
  it('creates a quiz successfully', () => {
    // --- Start user journey ---
    cy.visit('/quizzes/create');

    // Fill quiz title
    cy.getByLabel('Quiz Title').type('JavaScript Basics');

    // Fill question 1
    cy.getByLabel('Question Heading').type('What is a closure?');

    cy.getByLabel('Image URL (Optional)').type(
      'https://example.com/closure.jpg'
    );

    cy.getByLabel('Question Type').select('Single Choice');

    // Add two answers
    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer')
      .eq(0)
      .type('A function with preserved lexical scope');

    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer').eq(1).type('A CSS feature');

    // Submit
    cy.contains('Create Quiz').click();

    // --- Assertions ---

    // Success message
    cy.contains('Quiz created successfully').should('be.visible');

    // Redirect to quizzes list
    cy.url().should('match', /\/quizzes$/);

    // Check that the list shows the new quiz.
    cy.contains('JavaScript Basics').should('be.visible');
  });
});
```

Keeping the API and external dependencies such as local storage available and in
the right state can be difficult. In return, this test provides the strongest
resistance to refactoring. It **will pass** if we:

- Change the internal hook that creates the quiz
- Change the external API endpoint
- Change the internal quiz model
