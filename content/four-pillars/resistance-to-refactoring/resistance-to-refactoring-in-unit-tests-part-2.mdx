Tests of public functions usually provide more value, but they can still be
brittle. Consider this example:

```ts
import { createQuizModel } from './createQuizModel';
import * as validators from './validators';

jest.spyOn(validators, 'validateTitle');
jest.spyOn(validators, 'validateQuestions');
jest.spyOn(validators, 'validateAnswers');

describe('createQuizModel (brittle)', () => {
  it('calls validation functions in order', () => {
    validators.validateTitle.mockReturnValue('JS Basics');
    validators.validateQuestions.mockReturnValue([
      {
        heading: 'What is JS?',
        type: 'single',
        answers: [{ id: '1', text: 'A language' }],
      },
    ]);
    validators.validateAnswers.mockReturnValue(true);

    const form = {
      title: 'JS Basics',
      questions: [],
    } as any;

    createQuizModel(form);

    expect(validators.validateTitle).toHaveBeenCalledWith(form);
    expect(validators.validateQuestions).toHaveBeenCalledWith(form);
    expect(validators.validateAnswers).toHaveBeenCalled();
  });
});
```

This test uses Jest spies to check whether the validation functions received the
whole form. Suppose we change `validateQuestions` to accept only the questions:

```ts
function validateQuestions(questions: Question[]) {
  // implementation
}
```

The test will **break** even though **observable behavior** stays the same. This
false positive makes the suite less trustworthy. It happens because the test
checks internal steps instead of inputs and outputs.

Test the function with known inputs and expected outputs instead:

```ts
import { createQuizModel } from './createQuizModel';

describe('createQuizModel (resistant)', () => {
  it('returns a normalized quiz model when input is valid', () => {
    const form = {
      title: '  JS Basics  ',
      questions: [
        {
          heading: ' What is JS? ',
          type: 'single',
          answers: [' A language '],
        },
      ],
    };

    const result = createQuizModel(form);

    expect(result).toEqual({
      title: 'JS Basics',
      questions: [
        {
          heading: 'What is JS?',
          type: 'single',
          answers: [{ id: '1', text: 'A language' }],
        },
      ],
    });
  });

  it('throws when answers are invalid', () => {
    const form = {
      title: 'JS Basics',
      questions: [
        {
          heading: 'Question',
          type: 'single',
          answers: [],
        },
      ],
    };

    expect(() => createQuizModel(form)).toThrow();
  });
});
```

Mocks or spies inside a unit often couple tests to implementation details. Find
the most public function and test its **observable behavior** instead.

Prefer larger units of behavior when they remain easy to test.
