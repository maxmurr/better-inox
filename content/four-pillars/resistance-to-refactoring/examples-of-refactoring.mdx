Refactoring changes internal structure without changing observable behavior.
These React and Next.js examples show the difference between refactoring and a
feature change.

Ask one question:

> **Does the same input still produce the same observable output?** If yes, it
> is refactoring. If no, it is a behavior change.

### Example 1: Extract a component

Before:

```tsx
export function QuizCard({ quiz }) {
  return (
    <div className="card">
      <h2>{quiz.title}</h2>
      <p>{quiz.questionsCount} questions</p>
    </div>
  );
}
```

After, with the same output and a clearer internal structure:

```tsx
function QuizTitle({ title }: { title: string }) {
  return <h2>{title}</h2>;
}

function QuizMeta({ count }: { count: number }) {
  return <p>{count} questions</p>;
}

export function QuizCard({ quiz }) {
  return (
    <div className="card">
      <QuizTitle title={quiz.title} />
      <QuizMeta count={quiz.questionsCount} />
    </div>
  );
}
```

The user sees the same result. Only the internal structure changed.

**This is refactoring.**

### Example 2: Change what the user can do

**Before**

```tsx
return (
  {error && (
    <Alert
      variant="error"
      buttons={[
        <Button onClick={handleDelete}>
          Retry
        </Button>,
      ]}
    >
      Deleting the quiz failed.
    </Alert>
  )}
  ...
```

**After**

```tsx
return (
  {error && (
    <Alert variant="error">
      Deleting the quiz failed.
    </Alert>
  )}
  ...
```

This change removes the user's option to retry the deletion. An integration test
that covers retrying should fail.

**This is not refactoring.**

### Example 3: Change the quiz sorting algorithm

Suppose our quiz app sorts quizzes by title:

**Before**

```ts
const sorted = quizzes.sort((a, b) => a.title.localeCompare(b.title));
```

**After**

```ts
const sorted = quizzes.toSorted((a, b) => {
  return a.title.localeCompare(b.title);
});
```
