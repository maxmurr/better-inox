Integration tests cover multiple components, hooks, and some out-of-process
boundaries. Because they exercise more code, they catch more regressions than
unit tests.

Consider the earlier example of creating a quiz. A unit test can check the
output of _createQuizModel()_:

```ts
import { createQuizModel } from './createQuizModel';

describe('createQuizModel', () => {
  it('creates a valid quiz model from user inputs', () => {
    const form = {
      title: '  JavaScript Basics  ',
      questions: [
        {
          heading: '  What is a closure?  ',
          imageUrl: '  https://example.com/img.jpg  ',
          type: 'single' as const,
          answers: ['  A function with preserved scope  ', '  A CSS feature  '],
        },
      ],
    };

    const result = createQuizModel(form);

    expect(result).toEqual({
      title: 'JavaScript Basics',
      questions: [
        {
          heading: 'What is a closure?',
          imageUrl: 'https://example.com/img.jpg',
          type: 'single',
          answers: [
            { id: '1', text: 'A function with preserved scope' },
            { id: '2', text: 'A CSS feature' },
          ],
        },
      ],
    });
  });
});
```

This unit test does not show whether these parts work together:

- Page navigation
- Form inputs
- Form buttons
- Data submission

An integration test checks that wiring and the full journey for creating a quiz.
Here is a Cypress integration test for a Next.js app that uses a server action:

```ts
import { useCreateQuiz } from '@/features/quizzes/useCreateQuiz';
import { useRetrieveQuizzes } from '@/features/quizzes/useRetrieveQuizzes';

describe('Create Quiz', () => {
  it('creates a quiz successfully', () => {
    // --- Stub backend adapters (server action) ---
    // Return a successful response when the form submits.
    cy.injectFakeAdapter(useCreateQuiz, {
      body: {
        id: 'QUICK_ID',
        title: 'JavaScript Basics',
        questionsCount: 1,
      },
    });

    // --- Start user journey ---
    cy.visit('/quizzes/create');

    // Fill quiz title
    cy.getByLabel('Quiz Title').type('JavaScript Basics');

    // Fill question 1
    cy.getByLabel('Question Heading').type('What is a closure?');

    cy.getByLabel('Image URL (Optional)').type(
      'https://example.com/closure.jpg'
    );

    cy.getByLabel('Question Type').select('Single Choice');

    // Add two answers
    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer')
      .eq(0)
      .type('A function with preserved lexical scope');

    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer').eq(1).type('A CSS feature');

    // Submit
    cy.contains('Create Quiz').click();

    // --- Assertions ---

    // Success message
    cy.contains('Quiz created successfully').should('be.visible');

    // Redirect to quizzes list
    cy.url().should('match', /\/quizzes$/);
  });
});
```

This broader protection reduces two other attributes:

- **Maintainability.** An integration test requires more setup and coordination.
- **Feedback speed.** Running the UI takes longer than running a function in
  memory.
