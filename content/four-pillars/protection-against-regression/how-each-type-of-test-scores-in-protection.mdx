Protection against regressions measures how well a test catches broken behavior
after code changes. We can now add it to our comparison:

```
|             | Maintainability | Feedback Speed | Protection      |
|-------------|-----------------|----------------|-----------------|
| Unit        | High            | High           | Low to Medium   |
| Integration | Medium          | Medium         | Medium  to High |
| E2E         | Low             | Low            | High            |
```

**Unit tests.** They cover small portions of code, such as functions and
classes, which limits how many regressions they can catch. Tests of complex,
business-critical units provide more protection, so unit tests score **low to
medium**.

**Integration tests.** They exercise user journeys across components, hooks, and
stubbed boundaries. Their broader coverage gives them a **medium to high**
score.

**E2E tests.** They run the whole system as a user experiences it, including the
UI, APIs, database, and external services. They provide the **highest**
protection against regressions.

This pillar reverses the earlier scores. Tests that are harder to maintain and
slower to run also catch more regressions. The final pillar completes this
trade-off.
