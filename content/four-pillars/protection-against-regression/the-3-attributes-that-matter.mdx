Three attributes determine how well a test protects against regressions,
according to Vladimir Khorikov:

- How much code the test covers
- How complex that code is
- How important that code is to the business

Tests that execute more code, branches, and interactions can catch more bugs.
Tests that cover one small function can catch bugs only in that function.

**Complexity** also matters. Straightforward code leaves less room for mistakes.
Complex code with several branches is more likely to contain regressions,
especially as it grows.

**Domain significance** describes how important the code is to the business.
Tests of critical business functions provide more protection because failures in
those functions have a greater impact.

A test scores well when it exercises a broad section of production code and its
dependencies, especially complex or business-critical behavior.
