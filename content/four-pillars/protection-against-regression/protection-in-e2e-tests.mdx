End-to-end (E2E) tests run your application from the user's perspective with its
external dependencies available. These may include:

- APIs
- Databases
- File systems
- Cloud storage
- Authentication systems

Users interact with the real system, not fake APIs or stubbed credentials. E2E
tests provide the most protection against regressions. They can catch problems
in components, pages, API integrations, and other user-facing behavior.

Here is an E2E test for the same quiz page:

```ts
describe('Create Quiz', () => {
  it('creates a quiz successfully', () => {
    // --- Start user journey ---
    cy.visit('/quizzes/create');

    // Fill quiz title
    cy.getByLabel('Quiz Title').type('JavaScript Basics');

    // Fill question 1
    cy.getByLabel('Question Heading').type('What is a closure?');

    cy.getByLabel('Image URL (Optional)').type(
      'https://example.com/closure.jpg'
    );

    cy.getByLabel('Question Type').select('Single Choice');

    // Add two answers
    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer')
      .eq(0)
      .type('A function with preserved lexical scope');

    cy.contains('Add Answer').click();
    cy.getByLabel('Enter answer').eq(1).type('A CSS feature');

    // Submit
    cy.contains('Create Quiz').click();

    // --- Assertions ---

    // Success message
    cy.contains('Quiz created successfully').should('be.visible');

    // Redirect to quizzes list
    cy.url().should('match', /\/quizzes$/);

    // Check that the list shows the new quiz.
    cy.contains('JavaScript Basics').should('be.visible');
  });
});
```

This test resembles the integration test, but it does not use stubs. Its
complexity sits in the environment instead of the test code.

Every dependency must be available and in the right state. For example, if quiz
names must be unique, the test must remove any quiz with the same name before it
starts.

E2E tests also depend on the speed of external systems. If an API takes several
seconds to respond under load, the test takes longer too. This strong protection
comes with the lowest **feedback speed** and **maintainability** in the test
pyramid.

Use E2E tests for **critical user journeys** such as authentication, payment,
and enrollment.
